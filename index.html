Spring Labs · Zanko exercise

Two short builds, one link

Both tasks were approached the same way: personas → scenario → requirements → diagnosis/design → working prototype, with every design element traceable to a requirement and every requirement traceable to a moment in a user's day. Prototypes are built in code, in Zanko's existing design language, so they read as the next release of the product rather than a re-imagination of it.

Task 1 — Case View redesign

The one-sentence diagnosis: the current case view renders the database record, not the analyst's job — no workflow position, no next action, and AI conclusions presented as bare scores she can neither interrogate nor correct.

Read the diagnosis & design reasoning  Open the clickable prototype

In the prototype, use the demo bar (bottom) for the key states — long complaint, low-confidence AI, an analyst override, an overdue SLA, and resolution — and toggle Design notes to see each element pinned to the requirement it serves.

Task 2 — What should Zanko Reporting do next?

The one-sentence synthesis: all three quotes describe the same missing capability — Zanko can make the report, but nobody is served by how it reaches people. The feature is Scheduled Reports: subscribe each audience to the version they need, delivered by email on a cadence, with an approval gate for external sends.

Read the framing & scoping  Open the clickable prototype

In the prototype, press ▶ Tour for the guided walkthrough — the schedules list, the create flow with live email preview, the approval gate, the phone-sized executive email, and a failed delivery.

AI tools used & time spent

Tools: Claude Code (Anthropic) end to end — reading the brief, drafting the diagnosis, and building this site and the prototypes in plain HTML/CSS/JS. An independent AI review pass was run against the diagnosis before finalizing (it caught one misreading of the current screen, which was corrected — the kind of check I'd run on my own work regardless of tooling). No frameworks, no build step; hosted on Netlify.

My role vs. the AI's: the problem framing, the requirements, the scoping calls (what's in, what's out), and every design decision were mine to direct and approve; the AI accelerated the reading, writing, and construction.

Time: ~5–6 hours total across the two tasks, within the brief's 4–6 hour target.
